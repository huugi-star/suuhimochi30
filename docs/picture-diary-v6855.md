# 絵日記 v6.8.55：アプリ接続

## 使い方

設定の「ことばの絵日記」で送信に同意すると有効になる。初期状態はOFFで、通常の会話・ことばコンボ・タスク・旅・日誌はOFFのまま使える。同意は端末に保存し、30日サイクルで聞き直さない。

同意した日の学習から対象とし、JSTの翌日にアプリを起動、または非表示から復帰した最初の表示時に、昨日分だけを確認する。開きっぱなしで0時になったことを理由に画像を生成しない。未利用日の遡及生成や定期Cronはない。生成中も部屋を操作できる。

日誌の「ことばの絵日記」に、確認中・生成待ち・材料不足・利用不可・生成済みの状態を表示する。画像は別タブでも開ける。保存期限はWorkerから返った実際の値を日本時間で表示する。「画像を再確認する」はlookupのみで、再生成はしない。

## 必要なサーバー設定

| 設定場所 | 名前 | 設定内容 |
| --- | --- | --- |
| 情報センターWorker Secret | `DIARY_API_TOKEN` | 32文字以上。アプリ側と同じ値。 |
| アプリのサーバー環境変数 | `DIARY_API_TOKEN` | Workerと同じ値。ブラウザ公開変数にはしない。 |
| アプリのサーバー環境変数 | `DIARY_SESSION_SECRET` | 別の暗号学的にランダムな32文字以上の署名鍵。再起動・複数インスタンスで同じ固定値を使う。 |

本番はHTTPSで動かす。Cookieは開発時も `Secure` を外さず、ブラウザのlocalhost例外を使ったテストで確認した。匿名セッション用の鍵を変更すると、既存のCookie・所有権証明が無効になるため、通常のデプロイで作り直さない。アプリAPIの実行時間は90秒を確保する。環境変数設定後はサーバーを再起動・再デプロイする。

実際のSecretはコード・画面・ログに出力しない。2026-10-26、利用者によるサーバー環境変数の設定後、匿名セッションの発行とWorkerのBearer認証が成功した。

## 匿名認証と所有権

アカウント登録やログイン画面は追加していない。絵日記を最初に接続するときに、サーバーがランダムな匿名所有者ID・セッションを発行する。

- Cookie：`__Host-suuhimochi-diary`、HttpOnly、Secure、SameSite=Strict、Path=/、有効期間1年。
- サーバーの署名で改ざんを検証する。匿名Cookieの所有者・既存のローカル個体ID・実際に保存された生活開始日を対応づけ、サーバー専用の個体IDを発行する。
- 署名付きの個体証明を返す。画像APIではCookieと証明の所有者が一致することを検証し、検証済みIDだけをWorkerへ渡す。クライアントの `ownerId`、`companionId`、`startDate` 指定は画像APIで受け付けない。
- 所有権の対応は署名でサーバーが確定し、同じ署名鍵とCookieならサーバー再起動後も同じIDになる。追加の認証DBや外部ログインサービスは不要。
- Same-Origin POSTを必須にし、Cookie・証明の偽造、別オリジン、別匿名ユーザーの証明を拒否する。
- Cookieを消すと別の匿名利用者になる。旧匿名所有者の画像をローカル個体IDだけで他者が取得できるような復元は行わない。既存のローカルセーブは変更しない。

## 辞書から送る内容

昨日の新語→昨日再訪した語→過去の既知語の順で最大24語。大・中カテゴリーは既存のカテゴリー定義のラベルを使う。

- `word`：既存単語の表記。
- `majorCategory` / `subCategory`：既存の大・中カテゴリー。
- `firstLearnedAt`：既存の初回登録時刻 `learnedAt`。日時不明なら省略。
- `lastLearnedAt`：既存の記憶エピソード、またはユーザーが単語をそのまま入力した記録の実時刻。文章の部分一致はしない。記録不明なら省略。
- `relatedWords`：実在するACTIVEなRELATED_TO関係の先にある既存語だけを最大6語。説明文・属性・評価から関連語を生成しない。

日付はタイムゾーン付きISO形式またはJST日付を使う。`firstSeenDay` や `lastUsedDay` の番号から時刻を捏造しない。既存の午前7時基準の会話・日誌の日付処理は変更しない。

プロフィール名や家族・友人などの私的な人物カテゴリーを除外する。サーバーでも、既存の共通知識辞書に収録された一般語、または検証済み共有辞書との完全一致を通った語だけを送る。共通知識辞書の一般語だけなら共有辞書の通信を必要としない。ユーザー申告カテゴリーだけを共有可否の根拠にはしない。関連語にも同じ検証を行う。条件を満たす語が2語なければ「描く材料がまだ足りない」と表示し、別の語を補わない。

日誌本文、会話ログ、選択肢の回答、個人情報、感情・好み、単語の説明文、セーブ全体は送信しない。会話記録は端末内で再訪日時だけを取り出すために参照し、元の文章を外へ渡さない。

## Worker APIの呼び出し

1. サーバーで同意・匿名セッション・個体所有権を検証。
2. 対象日がJSTの昨日、かつ保存された生活開始日から30日以内であることを検証。
3. 認証付き `GET /diary/lookup`。
4. 200 / OK / generated / imageUrlなら保存し、plan・generateは呼ばない。
5. 202なら生成待ちまたは失敗の状態を表示し、再生成しない。
6. 404 / NOT_GENERATEDを確認した場合だけ、選んだ語を検証し `POST /diary/plan`。
7. PLAN_OKと選択語を検証し、同じJSONで `POST /diary/generate`。planIdは使わない。
8. 返却の `/diary/image?token=...` にWorkerオリジンを補い、その画像URLを保存・表示する。画像閲覧用トークンはWorkerの仕様で返るもので、サーバー専用のDIARY_API_TOKENとは別。

全て固定のWorkerオリジンを使い、任意URLやリダイレクトへBearerを転送しない。返却本文・例外に含まれる秘密情報を画面やログへ出さない。期待した応答と違う場合は生成しない。

## 保存・重複防止・Day30

同意、昨日用の最大24語の材料、個体証明、対象日別の画像URL・状態は新しい端末内キーに分離して保存する。既存GameSaveのタスク・日誌・報酬などへ書き込まない。生成を始める前に対象日の試行を保存し、保存できない場合は送信自体を停止する。

再起動後に中断記録があればlookupのみ。生成済み・材料不足は自動再試行しない。同時要求は端末・サーバーでもまとめ、複数インスタンス間はWorkerの重複防止も使う。

代替わり直前に旧個体の最大24語を保存し、辞書のリセット後もDay30の翌日に処理できる。同日に旧個体のDay30と新個体のDay1がある場合は、個体を混ぜず最大2件を順番に確認する。古い日付を列挙して生成するキューは作らない。材料の保持は当日・前日だけ。画像URLと状態は最大360件を端末に残す。

## 検証

`npm run test:picture-diary` と `npm run test:picture-diary:browser` を使用する。ブラウザは既存テストと同じPlaywright/Chrome指定環境変数を使い、隔離したセーブデータと模擬Worker応答で確認する。実際の画像AIは呼ばず、テスト画像は「検証用」と明示した固定画像である。

確認項目は、同意OFF、なりすまし・Cookie偽造・別オリジン拒否、キー非公開、最大24語、日付の捏造防止、lookup済み画像の再利用、材料不足、同時要求、再起動、保存不可時の非送信、JST0時、Day30翌日、同日の新旧個体、PC・スマートフォン表示。通常会話・デイリーミッション・起動・共有知識の既存テストも実行する。

2026-10-26の結果：新規単体16件、ブラウザ6ケースが成功。既存会話181件、デイリーミッション15件、起動14件、外部ひとり言17件、共有知識17件も成功した。TypeScript型チェック・対象lint・本番ビルドが成功し、ブラウザ用JavaScriptに絵日記のサーバーSecret変数が含まれないことも確認した。PCとスマートフォン横画面のスクリーンショットを目視確認済み。

設定後の本番結合テストでは、専用の匿名テスト個体に対して、一般語「野球」「サッカー」から実際のWorker画像を1枚生成した。実ユーザーのセーブデータは使用・変更していない。学習日時の記録は捏造せず省略した。lookupで未生成を確認してからアプリ経由で生成し、繰り返しのlookupでは同一画像が返ることをバイナリハッシュでも確認した。PCとスマートフォン横画面の日誌で実画像の表示を確認した。

この確認で見つかった「共有辞書未収録の一般語まで材料不足になる」問題を、既存共通知識辞書の完全一致を再利用して修正した。再発防止テストを追加し、単体テストは17件成功。型チェックと本番ビルドも成功した。設定後のビルド成果物・ソース・ビルドログに実際のSecret値が含まれないことを検査し、環境変数ファイルとテスト用セッションファイルがGitの管理対象外であることも確認した。

本番確認スクリプトは `npm run verify:picture-diary:live`。既定ではlookupだけを実行し、`-- --generate` を明示した場合に限り未生成のテスト画像を最大1枚生成する。`-- --browser` で生成済み画像を隔離したブラウザのPC・スマートフォン表示で確認する。認証情報は無視対象の `node_modules/.cache/picture-diary-live/private-session.json` にのみ保持し、ログやレポートには出さない。生成途中の記録がある場合は自動再生成しない。

遡及生成、30枚ZIP、Google Driveアップロードは実装していない。Cloudflare Workerのコードや設定も変更していない。
