# 今日の日誌と日付索引

今日だけ `TodayJournalTasks.tsx` と専用CSSを使用する。過去用の `JournalTasks.tsx`、`JournalTasks.module.css`、`JournalPanel.module.css`、絵日記の表示・APIは変更していない。

- 上部はDAY・日付・「きょうの日誌」。見出しは「きょうの予定」。
- 予定は1件ずつ表示し、前後ボタンで切り替える。「できた・途中・まだ」は48pxのボタンで、色と枠線により選択状態を示す。今日の花丸・押印アニメーションはない。
- 「予定を書く」「＋追加」、文面修正は既存の入力シートを利用する。結果の保存は従来の `saveJournalChecklistItem` を使用する。
- 「明日のもくひょう」は短い追加欄と登録件数を表示する。登録済み一覧・編集はシートで開く。編集ではID・登録日時・状態・対象日を維持する。
- 今日の予定・明日の目標は編集シートから確認後に削除可能。`removeJournalItem` は今日・明日だけを許可し、過去の記録と既存の報酬・ミッション達成履歴を変更しない。
- 今日には会話・ことば・軍師・六占の履歴メニューを表示しない。過去では従来どおり表示する。
- 通常のスマホは縦1列、低い横長画面は2列で主要操作を収める。長い単一の予定や文字拡大時には紙面内スクロールで全文を保持する。
- 今日の入力シートだけ `fitVisualViewport` を有効にし、キーボードで表示領域が縮んだ場合に高さを追従する。明日の入力欄もVisual Viewportに追従し、入力位置へスクロールする。過去のシートの動作は変更しない。
- 暦日の予定と午前7時の活動日・ミッション集計は既存の定義を維持する。

## 左端の日付索引

Git履歴のDAYタブ形状・暖色・日付を開く処理を再利用し、`JournalDateIndex.module.css` で左端に復元した。索引は独立してスクロールし、選択日を強調する。本文の幅・絵日記のサイズは変更しない。

今日と、日誌・予定・絵日記・会話・単語・軍師・六占などの保存済み記録がある日だけを列挙する。未来日と未作成日は開かない。過去ページの前後移動も作成済みの日付を移動する。

## 検証

実際のJournalPanel・PictureDiaryCardを使い、360×640、375×667、390×844、680×370、650×350、1365×900を検証する。今日の1件切り替え、全3結果の保存復元、追加・編集・削除・二重登録防止、明日の追加編集、索引による日付移動と索引だけのスクロールを確認する。

過去2日×6サイズ×絵日記/行動一覧の24画面を変更前と比較する。画像矩形・コメント・履歴4メニュー・記録のDOMを照合し、PNGの本文も比較する。許可された共通ナビゲーション部分は画像比較対象から除く（左の綴じ代25px、旧右索引の重なり6px、下部ナビゲーション55px）。画像境界の描画差だけ最大12画素・10階調を許容する。

375×667ではキーボード相当の縮小した表示領域もテストする。これはブラウザ上の模擬検証であり、実機キーボードの確認ではない。長い予定文は全文を維持し、スクロールして結果ボタンを操作できることも検証する。

TypeScript型チェック、明日の編集・翌日引き継ぎ・削除範囲・報酬維持のテスト、既存の日誌チェックリスト・デイリーミッションテストを実行する。実ゲームのPC・スマホではミッションからの日誌入力とミッション更新も検証する。

スクリーンショットと比較記録: `outputs/verification/today-journal/`。`SUUHIMOCHI_JOURNAL_BASELINE=1` は変更前の過去画面を記録するときだけ使用する。

確認結果：TypeScript型チェック成功。6サイズのブラウザテスト、過去24画面比較、375×667のキーボード相当表示・長文操作、今日用保存テスト、既存チェックリスト10件・ミッション15件が成功。実ゲームのミッション導線はPC・スマホ両方で成功。
