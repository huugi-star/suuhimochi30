# 開発者モード：外部話題モニター

2026-10-19のv6.4対応：現在は情報源別の「公開→受信→変換→端末保存→会話候補」、最終成功・エラー、詳細な除外理由も表示する。
再取得は端末とアプリサーバーの両キャッシュを迂回する。詳細は[external-v64-fix.md](./external-v64-fix.md)。以下の初版記録よりこちらの仕様を優先する。

開発版の部屋左下「DEV」→「外部話題」で開く。本番版では従来どおり開発者UIを表示しない。
既存の「通常」タブの開発操作はそのまま利用できる。

## 表示

- 最終取得日時、情報の更新日時、通信試行日時、ブラウザキャッシュ状態、取得中表示。
- Google／Wikipedia／YouTube／情報源不明の件数、取得件数、有効話題数、現在の候補数、個体の実使用回数。
- 話題のタイトル、情報源、大・中カテゴリー、取得・更新日時、出典リンク、判定状態、使用した活動日・Day・会話の種類。
- 一致した既知語・コンボ派生語、その起点、照合方法、根拠、採用・不採用の理由。
- 情報源、採用状態、使用状態による絞り込み。

取得件数は公開レスポンスから診断した項目数。有効話題数は安全性・鮮度検証後、重複除去と情報源ごとの500件上限を適用した件数。
そのため取得件数と有効話題数は異なる場合がある。3情報源と情報源不明の合計が取得件数になる。
取得一覧から消えた使用済み話題は、現在の取得数に加算せず既存の個体履歴から別途表示する。

非公開データを追加取得しない。アプリ側で受信した公開項目のうち、古い情報・分類不正・除外指定も診断に残す。
危険なタイトルは安全な代替表示、不正なURLはリンクなしとする。応答本文や任意の例外文、Secretは表示しない。
旧キャッシュに診断項目がない場合はその旨を表示し、正常取得後に補う。取得失敗はHTTP番号・タイムアウト等の固定コードで表示する。

## 会話との一致と採用

selectExternalMatchとモニターは同じevaluateExternalTopicsを使う。
既知語の一致、実際の派生語、明示的な別名、中カテゴリー＋追加根拠という既存の優先順位は変更しない。
「関連語なし」「以前使用済み」「古い情報」「否定・訂正した根拠」「当日使用上限」「優先候補」「ほかの候補を優先」を区別する。
優先候補はまだ使用済みではない。起動時に表示できるかどうかは既存の操作・睡眠・重要イベント等のUI制御が別途判断する。
起動機会の表示済みフラグはモニターから変更しない。

## 操作

「今すぐ再取得」は固定のGET /api/external-topicsを呼び、ブラウザキャッシュを読み飛ばす。
アプリサーバーの日次キャッシュも迂回するが、情報センターの収集Cronは実行しない。
通信失敗・全情報源の取得失敗時は、既存の正常キャッシュを保持してエラーを表示する。
有効期限切れのデータは診断にだけ残し、会話に復活させない。正常な空リストは以前のリストを置き換える。
並行リクエストはまとめ、遅れた応答同士が上書きし合わないようにする。

「会話プレビュー」は既存startupDiscoveryLinesによる2ページの台詞をモニター内に表示する。
ゲームの会話開始・表示確定・保存・報酬処理には入らない。関連根拠がない、または訂正済みの場合は生成しない。
過去の話題や当日上限の話題もテスト表示できるが、実際の会話採用とは区別する。
会話回数、使用履歴、辞書、仮面経験値、友好度、起動フラグは変更しない。
