# 起動・外部情報更新時の自発会話

## イベント制御

- Day2〜30：部屋を先に描画し、2フレーム後の起動機会に、準備済みのキャッシュから1件を選ぶ。日次表示済みフラグでは禁止しない。
- 起動ごとのランダムなイベントIDと既存のStartupOpportunityで、再描画・Strict Mode・二重コールバックを抑制する。同日リロードは新しい機会。
- 初期キャッシュがなくても通信を待たない。新しい公開データが後から届いた場合は、部屋が操作可能で、その通信開始後にユーザー操作がなく、直近30秒も操作していないときだけ更新会話を検討する。
- 起動中は1時間間隔と表示復帰で確認する。端末へ最終確認日時を保存し、失敗・再起動・連続復帰でも短時間の通信を抑制する。
- 公開APIだけを既存アプリAPI経由で取得する。定期確認と明示再取得は既存のrefresh=1を利用し、アプリAPIの日次キャッシュを越えて公開JSONを確認する。Worker/Cronは変更しない。
- 更新イベントは新しい話題IDまたは内容の変更を検知した場合に限る。内容指紋にはsource/id/title/url/category/subcategory/relatedTermsを使い、取得・更新・公開時刻は含めない。
- 個体ごとの内容指紋一覧を保存する。同じ公開データ・並び順の変更・時刻だけの変更・一度消えて同じ内容で戻った話題は再通知しない。
- 更新ごとに最大1件。自発会話の後15分は更新会話を開始しない。見送りを後から強制表示するキューは作らず、新しい候補自体は次回起動に使える。
- 通信開始時の入力世代と完了時の世代を比較する。pointerdown/keydown/wheelがあれば見送る。会話・各モーダル・日誌・軍師・六占・開発者画面・睡眠・別れ・卒業・非表示状態も優先する。
- Day1の起動イベントは対象外。既存の2会話目の興味取得とコンボ導線は維持し、その導線の後は新しい更新を利用可能。UIの会話・コンボが開いている間は割り込まない。

## 選出と会話

未使用を優先し、既知語の一致→コンボ派生語→明示的な別名・根拠のある分野→すうひもち自身の一般的な関心の順で選ぶ。
同じ優先度の候補では直近6回の情報源使用数と直前の情報源を考慮する。同じ情報源が2回連続した場合は、有効な別情報源の最優先候補を1回選ぶ。Googleの既知語一致が大量にあってもWikipedia/YouTubeを永久に押し出さない。
否定された関係を一般話題として再提案して迂回しない。再利用には24時間、直前と同じ話題には48時間の間隔を設ける。安全性・鮮度・公開停止の既存検証は維持する。

既存のズームUIに2ページ、選択肢・回答要求なしで表示する。再会・比較・勘違い・発見の言い方を使用回数で変える。どこでも1タップまたはEscapeで終了し、カメラ・操作を即座に復帰させる。放置時も自動終了。
一般話題は短い名前だけを入口にし、長いタイトルは読まない。タイトルから出来事・人気の理由を作らず、知らないことを明示する。ユーザーに教わった・好きだという説明を作らない。

例（実装関数から生成）：

1. 既知語：「動画の紹介を眺めていたら、マインクラフトにまた会ったの。」→「名前を知らない時は、たぶん通り過ぎていたよ。今日はちょっと、目が止まっちゃった。」
2. コンボ派生：「ゲームからつないだマインクラフト、動画の紹介にもあったの。」→「別々に見えた言葉なのに、教わった道をたどると、ちゃんと途中で会えるんだね。」
3. 自分の関心：ぼく、記事の名前の「オーロラ」が少し気になったの。→「名前を見ただけで、詳しくなった気になりかけちゃった。中身はまだ知らないんだった。えへへ。」

## 保存と保護

externalTopicHistoryには話題ID・情報源・日時・発動理由startup/update・イベントID・内容指紋・表示/スキップ/終了を保存する。最終使用日時は話題ごとの履歴から参照できる。
startupExternalAttemptsを互換拡張し、起動・更新の表示/見送りと理由を保存する。旧保存の日付だけのレコードは読み込むが新しい起動の禁止には使わない。
externalCatalogは差分検出専用。取得で辞書や意味記憶を増やさない。一般話題から架空の既知語やMemoryRelationを作らない。
SELF6＋LEARN6、仮面経験値、友好度、日誌、コンボ獲得・15秒制限は変更しない。既存の個体アーカイブには使用話題の拡張履歴が残り、次の個体の履歴・差分検出情報は空にする。
ホップ・ステップ・ジャンプや進捗確認の自動表示は復活させない。

## 開発者モニター

最終取得/更新確認日時、情報源別の取り込み件数、今回の新規件数、直近の内容更新、最後の使用話題、起動・更新の発動履歴と見送り理由を表示する。
明示再取得も同じ取得通知経路を通り、候補へ追加する。開発者画面では自動ズームしない。プレビューは保存や報酬に一切触れない。

## 検証コマンド

`npx tsc --noEmit`、`npm run test:external-autonomy`、`npm run test:conversation`、`npm run test:startup`、`npm run test:external-topics`、`npm run test:external-monitor`、`npm run test:external-v64`。
ブラウザは既存の`test:startup:browser`と`test:external-monitor:browser`を独立した保存領域・固定公開フィードで検証する。実サービスの更新を待たずに、追加・時刻のみ・遅延・失敗を再現する。
本番ビルドはWindowsの既存環境に合わせ`UV_THREADPOOL_SIZE=1`で実行する。
