# チェックで完成する手帳の日誌

2026-10-26更新：各項目の「できた・途中・まだ」に統一し、旧4段階の評価画面・入力・導線・新規評価保存処理を廃止した。

## 表示

- 過去のページは最上部に「すうひもちの日誌」を表示。生成済みの絵日記、短い既存コメント、その日やったこと、保存済みの文章日記を最初から並べる。全体の折りたたみは置かない。絵がなければ文章と行動記録だけ表示し、空白を作らない。長いページは紙面内でスクロールする。
- 今日の見出しは「きょうの日誌」。対象日で保存した予定を自動的に引き継ぎ、「できた・途中・まだ」の常時表示スタンプで状態を選ぶ。チェックボックスは置かない。「＋追加」で同じ紙面に入力欄を開き、完了した実績を直接記録する。鉛筆から項目の文章をその場で修正できる。独立した記帳画面を開かない。
- 下部の「あしたの予定」に入力すると翌日の予定として保存される。
- 昨日は「きのうの足跡」のしおりから、目標・過去の30日はコンパスから開く。会話・ことば・軍師・六占だけを索引シートへ収納する。
- 日誌内にデイリーミッションは表示しない。JST初回閲覧は昨日、同日の2回目以降は今日を表示する既存仕様を維持。
- 通常の今日のページ（引き継ぎ予定2件）は360×640・360×740・390×844に収まる。記録が多い場合や文字拡大時には単一の紙面スクロールを許可する。

## 保存と互換性

`journalChecklist` は既存 `taskPlans` と `journalNotes` をまとめて読み、同文は1行だけ表示する。既存の文字実績は完了として扱う。未指定の予定は「まだ」、既存の途中記録は「途中」として表示する。

`saveJournalChecklistItem` は予定のID・作成日時・所属日を保ち、単一の `result`（done / in_progress / not_done）と文章を更新する。完了判定は常に `result === done` から導き、別の完了フラグを保存しない。新しい実績や、修正した旧日誌項目は既存 `taskPlans` に `kind: 'actual'` を添えて保存する。完了した内容は既存の `saveJournalFootprint` を通じて `journalNotes` に同期する。「途中」「まだ」へ変えても項目は消えない。完了実績としての日誌本文には「できた」の項目だけが入る。同じ文章を再追加しても二重記録しない。

実績は予定登録・昨日の予定報告のミッション対象から除外する。既存の予定は従来どおりミッションへ反映する。過去日の後日編集も保存復元で保持する。友好度と経験のリンゴは既存の日付単位の重複防止を使う。卒業済みの記録の編集はアーカイブへ保存し、現在個体の報酬を増やさない。絵日記API・匿名認証・画像の対象日は変更しない。

旧 `dailyProgressRecords` / `lastDailyProgressActivityDate` とその評価値は移行で消さず、読み込み互換を維持する。新しい評価記録は生成しない。旧記録にある行動の文章だけは日誌として引き続き参照できる。「この日の進み具合」「この日を振り返る」と旧独立記帳フォームは廃止した。

## 確認

- `npm run test:journal-checklist`：予定と旧日誌の統合、重複、3択と完了判定の同期、旧4段階の復元、実績追加、文章修正、過去日保存復元、ミッション除外、報酬重複防止、アーカイブ編集。
- `npm run test:journal-layout`：JST初回表示・既存の日付と保存処理。
- `npm run test:journal-layout:browser`：PC・スマホ縦3サイズ・横画面。絵日記と文章日記、直接追加・修正・3択、途中状態の再起動復元、JST翌日への予定引き継ぎ、過去日追加、文字拡大、初日・卒業後・未完成画像。
- `npm run test:daily-missions` / `npm run test:daily-missions:browser`：既存ミッションと保存、JST日付切り替え、不要な報酬の防止。
- スクリーンショットと実測値は `outputs/journal-ui/` に出力する。絵日記は検証用の模擬画像を使い、有料生成を呼ばない。
- 既存Playwrightは `SUUHIMOCHI_BROWSER_PACKAGE`、Chromeは `SUUHIMOCHI_BROWSER_EXECUTABLE` で指定できる。
