# 外部情報と会話の接続

Day2〜Day30の新しい起動体験と任意の進捗確認については
[startup-experience.md](./startup-experience.md)を参照。以下は既存の外部連携の基本仕様。

## 初日の導線

初回の出会い演出・目標設定は従来どおり。その後の通常会話は、
`DAY01_SELF_01` → `DAY01_CURIOUS_03`（興味の名前を自由入力し、大・中カテゴリーを選択）
→ 残りのSELF 5本 → 残りのCURIOUS/LEARN 5本。
既存IDを維持し、SELF 6本・LEARN 6本、計12本を増やしていない。

興味の分類終了後に、ことばコンボへ進むかを選べる。開始する場合はその単語を既存の
親選択・履歴処理へ渡す。コンボの「おしまい」を押した時に、既存語と実際の派生路線を
使って外部の話題を探す。この演出では通常会話の回数を増やさない。
一致しない場合・通信失敗時は、一度だけ「道ができた、外のつながりはまだ見つからない」
という短い余韻で終える。無関係な話題で埋めない。

## 取得と検証

ブラウザ → `GET /api/external-topics` → 情報センターの `/safe-trends` と `/safe-youtube`。
リクエストは固定URLのGETのみ。単語・派生路線・回答・個人情報は送らない。
起動を待たせずバックグラウンドで取得する。

- 情報センターWorkerは変更していない。
- サーバーはプロセス内、ブラウザはlocalStorageで日本時間の日付単位にキャッシュ。
- 通常は端末あたり1日1回。5分ごとの確認や画面復帰では有効なキャッシュを読むだけ。
- 翌日になると再取得し、前日のデータを失敗時の代替には使わない。
- 一方の公開APIが失敗しても、もう一方の正常なデータは使える。失敗時は5分で再試行可能。
- 上流タイムアウト4.5秒、ブラウザ側6秒。応答は1MB・200項目/フィードまで。
- フィード更新36時間以内、YouTube公開7日以内、ほかの話題72時間以内。
- 未分類、不正なカテゴリー組合せ、停止・非公開・staleフラグ、不正URL、HTML・制御文字等は除外。
- 空の公開リストも新しい正しい結果として扱い、以前の話題を残さない。

公開停止は次の日次取得時に反映する。キャッシュ期間中の即時停止通知を受信する機構はない。
会話済み履歴は当時の個体の記憶として残るが、現行フィードへ再投入しない。
Google/Wikipediaの実際の公開リストは2026-10-18の接続確認時点で空だったため、
両者の項目処理は契約形式のテストデータで検証し、YouTubeは実データでも接続確認する。

## 選択・会話・記憶

照合は端末内。優先順位は明確な語の一致 → 実際のコンボ派生語 → 小さな明示的別名辞書
→ 中カテゴリーと本文の語による追加根拠。大カテゴリーのみでは採用しない。
包括的な意味推論や任意のタイトルの要約・事実生成は行わない。
「音楽」「ゲーム」の入口はその語自身の中カテゴリーと、曲・作品などの本文の根拠が必要。
それを個別の作品への好意とは扱わない。

外部会話の発見・反応は一致の種類や派生経路に応じて構成する。
長いタイトルを台詞へ埋め込まず、確認用の出典リンクを回答画面に表示する。
内容を見た・詳しく理解した・人気の理由を知っているとは言わない。

Day2以降に独立したOTHER枠は現行コードにない。
そのため既存SELF会話の返答後に短く添えるか、用意された会話がない日に
ペットの近況・PERSON派生などの既存記憶会話を先に選び、候補がない場合に使う。
起動用の独り言を含め、最大1回/活動日（午前7時切り替え）で、同一話題はその個体の30日内で繰り返さない。

保存は既存の会話保存キーへ互換フィールドを追加。外部話題のID・出典・URL・更新時点・
既存語ID・派生起点ID・根拠・実際の台詞・日・回答原文・訂正状態を記録する。
`MemoryEpisode`と`MemoryRelation`も既存語IDでつなぐ。外部のノードは辞書のWordEntryにしない。
否定はUSER_CORRECTION/REJECTEDとして記録し、新しい話題IDでも同じ根拠を再使用しない。
広い親カテゴリー経由で訂正済みの経路を迂回することも避ける。
辞書内でIDを統合する既存処理では、外部履歴の参照も一緒に移す。

取得だけでは辞書・経験値・報酬・コンボを更新しない。
コンボは人間さんの選択時のみ。報酬は既存のイベントID・重複防止処理をそのまま使う。
30日終了時は`cycleArchives[].externalTopicHistory`へコピーし、新しい個体の履歴は空にする。

## 検証

- `npm run test:external-topics`：初日の通し、選択根拠、訂正、復元、日次・停止・異常応答、アーカイブ。
- `npm run test:conversation`：既存の会話・コンボ・記憶の回帰。初日の順序に関する期待のみ変更。
- `npx tsc --noEmit`、`npm run build`。
- 画像取得、ガチャ、POTENO-LINK、六占と各占いの既存スクリプト。

ブラウザの実際の操作を通した目視確認と、クライアントの会話回数を扱うテストは区別する。
統合テストは会話エンジンの開始・入力・分類・コンボ・外部回答・保存を通して検証する。

### 2026-10-18 確認結果

- 型検査成功。会話181件、外部連携13件成功。
- 画像取得・ガチャ・POTENO/軍師/六占の既存10スクリプトすべて成功。
- 新規取得・照合モジュールとテストの対象lint成功。
- 開発APIと生成済み本番APIの両方がHTTP 200で有効なYouTube 33件を返した。
- 実API結果を渡したDay1の会話エンジンでも、マインクラフトとの発見台詞と出典を生成できた。
- 本番トップページHTTP 200を確認。
- 通常のビルド実行はWindowsの依存配置時のEPERMで失敗。
  `$env:UV_THREADPOOL_SIZE='1'; npm run build`で最後まで成功し、本番サーバーも起動・応答した。
  一部の依存リンク作成にEPERM警告が残るため、Windowsでの通常並列ビルドは環境上の残課題。
- ブラウザの画面操作を通した目視検証は未実施。
