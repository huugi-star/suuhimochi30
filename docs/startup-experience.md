# Day2〜Day30の起動体験

2026-10-19更新：日次1回制限は解除。起動ごとの機会・1時間/表示復帰更新・一般話題への対応は[自発会話の仕様](external-autonomous-talk.md)を参照。

## 流れと操作

変更前は、日次の進捗確認→昨日の記帳・未記帳確認→部屋、という必須の入口があった。
変更後は、既存の描画準備が終わったら操作できる部屋を先に表示する。
その直後の短い機会に、準備済みの関連話題があり、操作・会話・モーダル・睡眠・重要イベントが
始まっていない場合だけ、既存ズームUIで2ページの独り言を表示する。
取得待ちはしない。何もなければ通常生活へ進む。通信完了時の更新会話も、操作中や他イベント中には割り込まない。
会話中はどこでも1タップ、またはEscapeで即座に部屋へ戻れる。放置しても自動終了する。
通常会話のSELF6＋LEARN6を消費しない。

Day1の出会い・目標設定、通常会話2本目での興味取得、ことばコンボの導線は変更しない。

任意の操作は以下から利用できる。

- 日誌→「きのうの足跡」：昨日の絵日記・行動記録を開く。各項目の「できた・途中・まだ」を直接編集する。
- 旧4段階評価画面と「この日を振り返る／この日の評価を見直す」は廃止済み。
- 日誌→「目標・行動方法を振り返る」：既存のTwoDayReviewTalkを任意で開く。
- 通常画面の目標表示→日誌：いつでも現在の目標を確認・管理。

旧評価画面・未記帳確認・重複する独立記帳フォームは起動制御から撤去した。TwoDayReviewTalkの自動勧誘、未記帳を促す生活中の台詞は停止している。旧保存記録や軍師・六占・卒業は維持する。

## 情報と起動機会

既存のexternalInfoClient・公開API・検証・キャッシュ・照合を再利用する。
新しい収集、意味解析、外部語の自動学習は追加しない。
覚えた語、ことばコンボの派生路線、明示的な興味に根拠があるものを優先する。関連がない場合は、すうひもち自身の関心として安全な一般話題を使える（ユーザーの好みとはしない）。
話題のタイトルの長い読み上げ、知っていない内容の創作、強制質問・選択肢はない。
発見・再会・知識との比較など、一致の種類と過去の使用数で短い台詞を変える。

部屋の描画後に二つのrequestAnimationFrameを経て、一度だけ起動機会を判定する。
それ以前のpointerdown・keydown、非表示タブ、他の操作中、睡眠などは機会を放棄する。
NO_TOPIC／BUSYは「表示済み」ではなく、見送った機会として保存する。
SHOWNはズームUIがマウントされ、話題を再検証できた場合だけ確定する。
終了はSKIPPEDまたはFINISHED。古いコールバックで二重保存・再開しない。
同一活動日の再起動でも別の話題を選べる。旧日次レコードは発動を禁止しない。
同一話題の再使用抑制と訂正済み関係の除外は、既存の外部会話履歴を共有する。

活動日・会話・報酬はgetActivityDateKeyの午前7時基準。手帳・予定・ミッションの表示日付は日本時間0時基準を使う。
公開フィードの技術的なキャッシュ更新日（日本時間0時）とは区別する。
新しい個体では起動機会の履歴を空にし、使用した外部話題は従来の個体アーカイブに残す。

## 保存・報酬

会話保存へ互換フィールドstartupExternalAttemptsを追加した。旧保存では空配列になる。
外部会話履歴のcontext=startupとstartupOutcomeを保存し、既存のMemoryEpisode／MemoryRelationを使う。
取得・候補準備・表示で辞書、仮面経験値、友好度、ことばコンボを増やさない。

日誌記帳は共通のjournalProgressで更新する。旧dailyProgressRecordsとlastDailyProgressActivityDateは互換読み込みのため残すが、新規の4段階評価や評価済みフラグは作らない。行動項目の状態はtaskPlansのresultへ保存する。
journalNotes、既存suuhimochiDiaries、experienceFruits、friendshipの既存構造・重複防止IDを維持する。
経験リンゴは従来どおり過去日の記帳から作り、sourceDateによる重複防止を利用する。
当日の日誌を記入しても当日中のリンゴを先取りしない。再保存で報酬を重複付与しない。
入力しない日は記録・報酬・失敗判定を作らない。

## 生成した台詞の例

以下はテストで生成した、マインクラフトとYouTube紹介の明確な一致による2ページの例。

1. 「動画の紹介を眺めていたら、マインクラフトにまた会ったの。」
   「名前を知らない時は、たぶん通り過ぎていたよ。今日はちょっと、目が止まっちゃった。」
2. 「マインクラフト、動画の紹介にも名前が出ていたの。」
   「人間さんと話した時のことを思い出したよ。同じ名前でも、まだ知らないところがあるんだね。」
3. 「動画の紹介にマインクラフトがあって、ぼく、少し立ち止まったの。」
   「知ってるつもりになりかけたけど、名前を知ってるのと、詳しいのは別だったね。えへへ。」

## 検証方法

- npx tsc --noEmit
- npm run test:startup
- npm run test:conversation
- npm run test:external-topics
- 画像取得、ガチャ、POTENO-LINK、六占・各占いの既存10スクリプト。
- Windowsでは `$env:UV_THREADPOOL_SIZE='1'; npm run build`。
- 本番サーバーを起動し、scripts/test-startup-browser.mjsを実行。
  コマンドは `npm run test:startup:browser`。
  SUUHIMOCHI_TEST_URL、SUUHIMOCHI_BROWSER_MODULES、SUUHIMOCHI_BROWSER_EXECUTABLEで
  対象URLと既存Playwright・Chromeを指定可能。ユーザーの保存領域は変更しない。

ブラウザではDay2起動→スキップ→日誌→任意評価→記帳・困難→再保存→再起動、翌活動日、
話題0件、通信遅延、睡眠中、自然終了を確認する。
フィードは再現可能なテストデータを使用し、実サービスのその日の話題の有無とは切り分ける。
実機スマートフォンのタッチ・表示差は未検証。
WindowsのNitro依存リンクのEPERM警告は残るが、単一スレッド設定でビルド・本番起動できる。
